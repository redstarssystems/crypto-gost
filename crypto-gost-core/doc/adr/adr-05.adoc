== ADR 05

*ADR:* scrypt (RFC 7914) использует JCA HmacSHA256 как внутренний PRF — осознанное исключение из hard-правила «только ГОСТ». +
*Контекст:* SCrypt (crypto-gost-core, org.rssys.crypto.util.SCrypt) реализует key derivation по RFC 7914 и вызывает javax.crypto.Mac.getInstance("HmacSHA256") для PBKDF2-PRF. Это единственное место в проекте, где применяется не-ГОСТ криптография; вызывается из KeyGenerator (не мёртвый код). Формально нарушает правило проекта «Только ГОСТ — никаких fallback на SunJCE/JDK». +
*Решение:* сохранить использование JCA HmacSHA256 внутри scrypt; не заменять на ГОСТ-PRF. +

*Обоснование:*

** RFC 7914 жёстко фиксирует HMAC-SHA-256 в качестве внутреннего PRF scrypt на уровне спецификации. Замена PRF на ГОСТ-примитив даёт несовместимую с RFC 7914 функцию, а не scrypt.
** «ГОСТ-scrypt» не существует ни в одном стандарте — совместимой ГОСТ-альтернативы для этого конкретного KDF нет.
** Изоляция: HmacSHA256 не используется нигде более; исключение локализовано в одном классе и явно помечено inline-комментарием.

*Принятый риск:* компрометация JCA-реализации HMAC-SHA256 (провайдера JDK) теоретически ведёт к утечке пароля/производного ключа. Практически JDK HmacSHA256 — устоявшийся, широко проверенный примитив; риск сопоставим с доверием к самой JVM. Severity: LOW.

*Граница применимости:* исключение распространяется исключительно на внутренний PRF scrypt. Любая другая криптооперация в проекте обязана оставаться на org.rssys.gost.*.

*Пересмотреть если:* появится стандартизованная ГОСТ-параметризация scrypt/PBKDF2 с совместимым PRF, либо scrypt будет выведен из состава поддерживаемых KDF.
