# PFX КриптоПро (PBE 1.2.840.113549.1.12.1.80): разбор формата

Дата: 2026-11-13. Репозиторий crypto-gost не менялся. Всё лежит в этом каталоге.

## Итог

Формат разобран полностью и подтверждён на 7 образцах, выгруженных `certmgr -export -pfx`
(CryptoPro CSP 5.0.13800): ключи 256 и 512 бит, пароли `demo`, `a`, 20 символов ASCII
и кириллический `пароль`. Во всех образцах извлечённый закрытый ключ побайтно совпал с исходным
ключом, известным заранее (образец создан crypto-gost и импортирован в CSP как экспортируемый).
Внутренняя имитовставка совпала во всех случаях. С неверным паролем расшифровка не даёт DER.

Основа взята из открытых описаний сообщества (ссылки внизу). Реализация в `Decode.java` написана
заново по описанию, без копирования кода. Сверх описаний подтверждено следующее:
- узлы замены на обоих слоях;
- проверка имитовставки (в cpfx её нет);
- точная схема для 512 бит: в cpfx она толкуется иначе;
- порядок байт ключа.

## Схема

Снаружи — обычный PKCS#12 по RFC 7292:
- MAC: HMAC-SHA1, KDF PKCS#12, 2000 итераций, соль 20 байт;
- сертификат: `pbeWithSHA1And3-KeyTripleDES-CBC`;
- ключ: `pkcs8ShroudedKeyBag`, алгоритм `1.2.840.113549.1.12.1.80`,
  параметры `SEQUENCE { salt OCTET STRING (16), iterations INTEGER (2000) }`.

OpenSSL проверяет MAC и расшифровывает сертификат. Нестандартен только key bag.

### Слой 1: пароль -> ключ K, расшифровка key bag

```
K0 = UTF-16LE(пароль)                      -- без BOM и без завершающего нуля
Kc = H94(Kc-1 || salt || BE16(c)),  c = 1..iterations   -- результат K = K_iterations (32 байта)
     H94 = ГОСТ Р 34.11-94, параметры хэширования КриптоПро (BC "D-A", RFC 4357 §11.2)
PT = ГОСТ 28147-89 CFB-64 расшифрование(K, IV = salt[0..8]), узлы замены CryptoPro-A (BC "E-A")
```
Дополнения нет (режим потоковый). Длина PT равна длине шифртекста: 176 байт для 256 бит, 210 для 512.

### Открытый текст слоя 1 (похож на PrivateKeyInfo)

```
SEQUENCE {
  INTEGER 0
  SEQUENCE { OID 1.2.643.7.1.1.1.1 (или ...1.1.1.2 для 512), NULL }
  OCTET STRING  value                                   -- экспортный блоб, см. ниже
  [0] { SEQUENCE { OID 1.2.643.2.2.37.3.10, SET { SEQUENCE { [1] IMPLICIT "20280213090423Z" } } } }
}
```
Атрибут `1.2.643.2.2.37.3.10` — дата окончания срока действия закрытого ключа (здесь +15 месяцев от импорта).

`value` состоит из двух частей:
- `value[0..16]` — заголовок PRIVATEKEYBLOB:
  `07 20 00 00 | 46 AA 00 00 | 4D 41 47 31 ("MAG1") | 20 00 00 00` для 256 бит,
  `07 20 00 00 | 42 AA 00 00 | 4D 41 47 31 | 40 00 00 00` для 512 бит.
  Последнее поле — длина ключа в байтах (0x20 / 0x40).
- `value[16..]` — DER:
```
SEQUENCE {
  SEQUENCE {
    OCTET STRING ukm (8)
    SEQUENCE { OCTET STRING encKey (32 | 64), OCTET STRING mac (4) }
    [0] IMPLICIT SEQUENCE {
        BIT STRING (флаги, 'a0')
        [0] IMPLICIT SEQUENCE { OID 1.2.643.7.1.1.6.1 (6.2 для 512),
                                SEQUENCE { OID кривой, OID хэша } } }
  }
  OCTET STRING (4)      -- назначение не установлено: нет ни в сертификате, ни в открытом ключе
}
```

### Слой 2: снятие обёртки ключа

```
KEK = KDF_GOSTR3411_2012_256(K, label = 26 BD B8 78, seed = ukm)
    = HMAC_Стрибог256(K, 01 || 26BDB878 || 00 || ukm || 01 00)     -- Р 50.1.113-2016 §4.5
d_le = ГОСТ 28147-89 ECB расшифрование(KEK, encKey), узлы замены CryptoPro-A
       -- 512 бит: ECB по всем 64 байтам (8 блоков), один ключ KEK
mac  == ГОСТ 28147-89 имитовставка(KEK, IV = ukm, d_le), 4 байта
       -- для 512 бит считается над всеми 64 байтами
d    = reverse(d_le)       -- в блобе ключ little-endian
```

## Что подтверждено опытами

| Образец | Ключ | Пароль | Слой 1 | d совпал | MAC |
|---|---|---|---|---|---|
| cp-256-pw_64656d6f | 256 | demo | E-A | да (LE) | совпал |
| cp-demo-1 | 256 | demo (другой экспорт) | E-A | да | совпал |
| cp-256-pw_61 | 256 | a | E-A | да | совпал |
| cp-256-pw_3031…6a | 256 | 0123456789abcdefghij | E-A | да | совпал |
| cp-256-pw_d0bf…8c | 256 | пароль | E-A | да | совпал |
| cp-512-pw_64656d6f | 512 | demo | E-A | да | совпал |
| cp-512-pw_61 | 512 | a | E-A | да | совпал |
| cp-256-pw_64656d6f | 256 | wrong | DER нет | — | — |

Длина шифртекста от пароля не зависит. Соль и UKM меняются при каждом экспорте.

## Не проверено

- Ключи ГОСТ Р 34.10-2001: ALG в заголовке другой. Чтобы получить образец, нужно сгенерировать ключ
  в CSP, а для этого требуется ДСЧ с участием оператора.
- Кривые, отличные от tc26 A (256 и 512); параметры КриптоПро A/B/C/XchA/XchB.
- PFX, выгруженные из cptools, Windows CSP и других версий CSP. Число итераций всегда было 2000.
- Назначение хвостовых 4 байт блоба и флагов `a0`.

## Что нужно для поддержки в crypto-gost (решения за пользователем)

1. **Новые примитивы в core.** Сейчас их нет: ГОСТ 28147-89 (узлы CryptoPro-A, режимы ECB и CFB-64,
   имитовставка) и ГОСТ Р 34.11-94 с параметрами КриптоПро. Оба алгоритма выведены из действия, поэтому
   их нужно держать только для чтения, без публичного API шифрования. Векторы для проверки:
   RFC 5830, RFC 5831, RFC 4357. KDF на Стрибоге-256 в библиотеке уже есть (`KdfGostR3411_2012_256`).
2. **Конфликт с правилом «только ГОСТ».** MAC файла считается по HMAC-SHA1, сертификат зашифрован 3DES.
   Варианты:
   - (а) реализовать SHA-1 и 3DES у себя только для чтения;
   - (б) использовать уже существующий явный `allowJdkFallback` в `GostPkcs12Loader`;
   - (в) не проверять MAC и не читать сертификат. Это отвергается: потеря целостности и неполный результат.
   Выбор за вами.
3. **Защита (fail-closed):**
   - проверять заголовок (07, ALG, MAG1, длина);
   - сверять OID ключа, кривой и хэша с сертификатом;
   - сравнивать имитовставку в постоянном времени;
   - сверять открытый ключ, полученный из d, с сертификатом;
   - ограничить число итераций сверху (защита от DoS);
   - затирать K, KEK, открытый текст и d_le.
4. **API.** Чтение через тот же `GostPkcs12Loader.load` с распознаванием OID 12.1.80 либо явный режим
   «унаследованный формат КриптоПро». Запись в этом формате не нужна: CSP уже импортирует наш PFX
   по RFC 9548.
5. **Тесты.** Образцы из `samples/` с известными d (пароли в именах файлов, hex). Нужен негативный набор:
   неверный пароль, испорченная имитовставка, неверный заголовок, несовпадение с сертификатом.
   В кросс-валидацию добавить тест: экспорт `certmgr` -> чтение crypto-gost.
