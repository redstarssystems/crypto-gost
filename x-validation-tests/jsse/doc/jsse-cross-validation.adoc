= Кросс-валидация JSSE ↔ OpenSSL
:source-highlighter: coderay

== Цель

Проверить, что реализация JSSE (https://docs.oracle.com/en/java/javase/21/security/java-secure-socket-extension-jsse-reference-guide.html[JSSE API])
библиотеки crypto-gost корректно взаимодействует с эталонной реализацией OpenSSL
(патченая сборка 3.6 с gostprov) на уровне:

* `GostSSLSocket` / `GostSSLServerSocket` (InputStream/OutputStream API)
* `GostSSLEngine` (wrap/unwrap ByteBuffer API)

Оба API должны быть совместимы с OpenSSL `s_client` и `s_server` для TLS 1.3 + ГОСТ.

== Методология

=== Серверные тесты

crypto-gost выступает в роли сервера, OpenSSL `s_client` — в роли клиента.

. crypto-gost создаёт `GostSSLEngine` (серверный режим) или `GostSSLServerSocket`
. Открывает TCP-порт, ждёт подключения
. `s_client` подключается, выполняет TLS 1.3 handshake
. `s_client` отправляет `GET / HTTP/1.0\nHost: example.com\n\n`
. Сервер отвечает `HTTP/1.1 200 OK\n...INTEROP_OK`
. Проверяется, что `s_client` получил строку `INTEROP_OK`

=== Клиентские тесты

OpenSSL `s_server` — в роли сервера, crypto-gost — в роли клиента.

. `s_server` запускается с ГОСТ-сертификатом на случайном порту
. crypto-gost создаёт `GostSSLEngine` (клиентский режим) или `GostSSLSocket`
. Выполняется TLS 1.3 handshake
. crypto-gost отправляет `GET / HTTP/1.0\nHost: localhost\n\n`
. Проверяется, что ответ содержит информацию о соединении

== Тестовые сценарии

=== Engine-сервер (GostSSLEngine + wrap/unwrap + TCP)

Ручной цикл wrap/unwrap через ServerSocket — эмуляция неблокирующего IO.

|===
| Тест | Сценарий | Кривые | Suite |

| roundtrip L | GET → INTEROP_OK | GC256B | L |
| roundtrip S | GET → INTEROP_OK | GC256B | S |
| все кривые | handshake | GC256B, GC512A, GC512B, GC256A, GC512C | L |
| mTLS | взаимная аутентификация | GC256B | L |

=== Возобновление по PSK

Тесты проверяют, что второе соединение возобновляется по тикету (`GostSSLEngine.wasResumed()`), с
обменом данными. Для обоих наборов шифров (L и S).

* `OpenSslJsseResumptionCrossValidationTest`: клиент `GostSSLEngine` с общим для двух соединений
  `GostSSLSessionContext` и менеджером доверия, сервер `s_server`. Кривые GC256B (группа клиента по
  умолчанию) и GC256A (клиент начинает с группы сервера через `setClientNamedGroup`, иначе каждое
  соединение идёт через HelloRetryRequest). Отдельный тест: тикет из рукопожатия с HelloRetryRequest
  возобновляется без него (проверка расчёта resumption master secret после HelloRetryRequest).
* `OpenSslJsseServerResumptionCrossValidationTest`: сервер `GostSSLEngine`, клиент `s_client`
  (`-sess_out`/`-sess_in`), кривые GC256B и GC256A. Отдельный тест: `s_client` предлагает `key_share` только
  для GC256A, сервер выбирает GC256B, оба соединения идут через HelloRetryRequest (по трассе `-msg` два
  ClientHello) и второе возобновляется.
* `CryptoproJsseServerResumptionCrossValidationTest`: сервер `GostSSLEngine`, клиент КриптоПро
  (`csptest -tlsc -proto 7 -reconnects 3 -checkreuse -checksessionticket`), кривая GC256A; сервер
  выбирает группу GC256A, как единственную в `key_share` `csptest`. Отдельный тест: сервер выбирает
  GC256B, а `csptest` присылает `key_share` только для GC256A, поэтому соединения должны идти через
  HelloRetryRequest. Это ожидание, а не измерение: число ClientHello тест не считает, и при смене поведения
  `csptest` он перестанет проверять HelloRetryRequest. Строгая проверка со счётчиком ClientHello - в tls13-тесте
  `CryptoproTlsResumptionTest.serverResumesCryptoproClientThroughHrr`. Второе и третье соединения возобновляются.

Binder второго ClientHello считается по RFC 8446 §4.2.11.2, внешняя сторона проверяет его независимо.

== Покрытие

* Проверки возобновления по PSK: клиент jsse с `s_server` (5), сервер jsse с `s_client` (6, из них 2 через HelloRetryRequest), сервер jsse с `csptest -tlsc` (4, из них 2 через HelloRetryRequest по ожиданию); остальное - `OpenSslJsseCrossValidationTest`
* 5 кривых: GC256B (CryptoPro-A), GC512A (TC26-512A), GC512B (TC26-512B), GC256A (TC26-256A, кофактор 4), GC512C (TC26-512C, кофактор 4)
* 2 cipher suites: L и S
* 2 API: SSLEngine и SSLSocket
* 5 размеров payload
* mTLS
* Group mismatch (fallback)
* Возобновление по PSK: клиент и сервер jsse, OpenSSL и КриптоПро, наборы L и S, с HelloRetryRequest и без него
* KeyUpdate после handshake (сервер `GostSSLEngine` с `s_client`)

== Требования к окружению

* OpenSSL 3.6+ с gostprov (патченая сборка)
* GOST TLS 1.3 cipher suites: `TLS_GOSTR341112_256_WITH_KUZNYECHIK_MGM_L` (0xC103) и `TLS_GOSTR341112_256_WITH_KUZNYECHIK_MGM_S` (0xC105)
* Java 21+ (virtual threads)
* Maven 3.8+
